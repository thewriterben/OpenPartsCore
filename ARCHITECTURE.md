# Architecture

```
schema/part.schema.json     the one definition of a part entry (JSON Schema 2020-12)
data/<namespace>/<id>.json  one part per file, schema-valid, cited
scripts/validate.py         stdlib validator: structure, citations, unit-suffix rules
bindings/                   generated code (Rust/TS/Python/C#) — never hand-edited (none yet)
```

## Grounding

This repo is reviewable reference data in the sense of OpenDesignCore ADR-0006: values arrive by pull request with citations, changes are visible in diffs. Downstream model runs may read values from here (via bindings) because every value is cited; nothing here is LLM-synthesised knowledge.

## Boards namespace ingest

`data/boards/` entries are derived from Oh-Ben-Claw `registry/registry.json` (schema_version 1) by `scripts/ingest_obc.py`. Upstream rows are USB *identities*, not boards, so the ingest **groups rows by board model** and carries the identities as `attributes.usb_ids` (ADR-0004): 69 upstream rows become 66 entries. Capabilities and connectors are unioned across merged rows; `source` records the upstream file and schema_version. Re-ingest is idempotent — an unchanged upstream rewrites nothing. OBC is not forked: corrections to board facts go upstream first.

Identifying a connected board is therefore a **match**, not a lookup — `303a:1001` narrows to 17 candidates and needs a second signal.

## Bindings

`bindings/<lang>/` is generated by `scripts/emit_<lang>.py` and committed. `--check` regenerates and diffs, so a data change without a regenerated binding fails rather than drifting (ADR-0003). TypeScript is first, for OBC-deployment-generator; it compiles under `tsc --strict`.

## What does not live here

- User inventory (mutable state; separate store referencing part ids)
- Pricing/stock (volatile; fetched live from distributor APIs by consumers, keyed by ids here)
- Kernel-side geometry (3D models are linked by path/hash, not embedded)
